# Top3 Documentation

This directory contains the product, design, architecture, planning, launch, legal, and historical documentation for Top3.

For the current implementation checkpoint, start with the root-level:

- `../CURRENT_STATE.md`

## Product Vision & Experience

- `product.md` — enduring product vision, mission, principles, and North Star
- `FEATURES.md` — current user-facing feature inventory
- `USER_JOURNEY.md` — intended end-to-end user journey
- `epics/FIRST_RUN_EXPERIENCE.md` — implemented V1 first-run / onboarding epic

## Design

- `DESIGN_SYSTEM.md` — visual language, theme architecture, reusable UI patterns, and design-system rules

## Architecture & Engineering

- `ARCHITECTURE.md` — long-term application architecture and architectural principles
- `TECHNICAL_ROADMAP.md` — technical foundations, provider architecture, constraints, and post-launch infrastructure direction
- `ENGINEERING_PRINCIPLES.md` — engineering practices and implementation principles
- `AI_DEVELOPMENT_CHARTER.md` — AI-assisted development guidelines
- `ANALYTICS_STATUS_2026-08-21.md` — historical analytics implementation checkpoint

## Product Planning

- `ROADMAP.md` — product milestones, current priorities, and future initiatives
- `V1_LAUNCH_BLOCKERS.md` — App Store V1 release-gate checklist and submission-readiness tracking

## Product History & Decisions

- `CHANGELOG.md` — significant implementation and product milestones
- `DECISIONS.md` — durable product decisions, including superseded decisions

## Legal, Privacy & Community

- `PRIVACY_POLICY.md` — repository copy of the Top 3 Privacy Policy
- `TERMS_OF_USE.md` — repository copy of the Top 3 Terms of Use
- `COMMUNITY_STANDARDS.md` — community behaviour and content standards

## Document Roles

Use each document for its intended purpose:

- **Current implementation state** → `../CURRENT_STATE.md`
- **What users can do today** → `FEATURES.md`
- **Why the product exists** → `product.md`
- **What should happen next** → `ROADMAP.md`
- **How the system is structured** → `ARCHITECTURE.md`
- **Technical direction and constraints** → `TECHNICAL_ROADMAP.md`
- **Visual and interaction rules** → `DESIGN_SYSTEM.md`
- **Durable product rules** → `DECISIONS.md`
- **Historical milestones** → `CHANGELOG.md`
- **Launch gate** → `V1_LAUNCH_BLOCKERS.md`
- **User-flow intent** → `USER_JOURNEY.md`

## Maintenance

Documentation should be updated when the corresponding product, architecture, design-system, launch-readiness, or legal state materially changes.

Avoid duplicating the same implementation detail across multiple documents when one document is already the source of truth.
